HDL / PROCESSOR DESIGN

Custom CPU with Pong.

A custom instruction set running an interactive game.

A 16-bit processor built in Verilog for the Basys 3 FPGA. The CPU executes the Pong game program, while dedicated hardware handles keyboard input and VGA rendering.

VerilogCustom ISABasys 3PS/2VGA

THE FOUNDATION

Building the 16-bit processor

The CPU combines a 16-bit ALU, sixteen general-purpose registers, an 8-bit program counter, instruction memory, and a control unit. The datapath reads operands, executes an operation, and selects an ALU result, memory value, or immediate for register writeback.

The ALU supports arithmetic, bitwise logic, shifts, and comparisons. Stored zero and carry/borrow flags drive conditional jumps in the game program.

  1. Custom CPU →Executes the Pong program and updates game state.
  2. Game registers →Connect instructions to inputs, positions, and scores.
  3. VGA rendererDraws the current game state directly to the display.

DEFINING THE INSTRUCTIONS

Designing a custom ISA

Instructions are 16 bits wide. The top bit selects the ALU or non-ALU class, followed by a four-bit opcode. ALU instructions read two registers and write the result back to the first; comparisons update the flags without writing a result.

The non-ALU class includes immediate loads, memory-mapped loads and stores, and unconditional or flag-based jumps. Immediate loads use a seven-bit constant, and jumps use an eight-bit instruction address.

CONNECTING THE GAME HARDWARE

Memory-mapped game state

Load and store instructions access the game registers at 0xF0 through 0xFD. The CPU reads key states and timing flags, then writes ball positions, paddle positions, directions, speed, and scores.

ADDING PLAYER INPUT

Reading the PS/2 keyboard

The receiver synchronizes the external PS/2 clock and data signals to the FPGA clock, detects falling clock edges, and captures scan-code frames. Start, stop, and odd-parity checks reject invalid frames.

A key-state module converts make and break codes into held-key flags. The CPU reads those flags through the keyboard register.

RUNNING PONG AS A PROGRAM

Movement, collisions, and scoring

The Pong program is encoded directly in instruction ROM using Verilog encoding functions and named jump targets. It polls the frame-ready register, which hardware sets every three VGA frames, then clears the flag before updating the game.

Each update moves the player paddle from keyboard input, moves the computer paddle toward the ball, and advances the ball using its direction and speed. Boundary and paddle checks reverse its direction. Paddle hits increase speed up to a fixed limit.

When the ball passes a paddle, the program increments the opposing score and resets the ball position and speed for the next round.

MAKING THE GAME VISIBLE

Rendering directly to VGA

The VGA driver generates 640 × 480 timing, pixel coordinates, and a frame-timing pulse. The renderer compares each pixel coordinate with the game registers to draw the ball, paddles, dashed center line, and seven-segment-style scores.

Graphics are generated as the display is scanned, without a framebuffer. Game coordinates are scaled by four for display, and the renderer outputs four bits each for red, green, and blue.
